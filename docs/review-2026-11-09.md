## 2. Critical upgrade areas (backend / engine / data)

### C1 — Windows persistence failure breaks the entire primary flow · P0 · measured

**Mechanism.** `atomic()` in `src/data/store.ts:47-56` writes temp → rename → `directory.sync()`. Directory fsync is POSIX-only; on Windows it throws `EPERM` *after* the rename succeeded. `writeDataset` (`store.ts:83-87`) calls `writeSnapshot` **first**, so the throw prevents the request index from ever being written. `src/runs/store.ts:173-174` repeats the same pattern. Because `capturedAt: new Date().toISOString()` is inside the hashed payload (`src/data/ingest.ts:105`), every refetch produces a new digest — an identical retry can never early-return.

**Blast radius (measured).**
- Direct probe: `loadMarketData` → `readDataset` MISS before *and* after a fetch; full stack terminates at `store.ts:54`. 3/3 `runReplay` calls fail with `BacktestInputError: EPERM…`.
- HTTP: 11/11 model-path `POST /api/backtest` → HTTP 400 with the raw EPERM string; the legacy path (no new fields) → HTTP 200.
- The UI **always** sends `fillModel` + `strategy` (`src/web/Configuration.tsx:55-59`), so every browser "Run backtest" takes the broken path. Confirmed live: the form's alert displays `EPERM: operation not permitted, fsync` verbatim.
- Each attempt refetches from the indexer (~4–20 s) before failing; snapshot files accumulate on disk while the index stays empty. 272 orphaned cache files from the old v2 layout also remain (code expects `v3/`).

**Upgrade direction.** Treat directory fsync as a best-effort durability hint: skip or catch `EPERM`/`EINVAL`/`ENOSYS` on non-POSIX platforms in both stores; guard the symlink test similarly. Map storage failures to a 5xx with human copy instead of wrapping them as `BacktestInputError` (`src/backtest-api.ts:191`) which leaks raw OS errors as a 400. Separately, reconsider `capturedAt` inside the content digest and the `to=now` default for relative windows — both guarantee cache misses for repeated identical requests.

### C2 — `/api/resample` is the one heavy endpoint without concurrency or work caps · P1 · code-level + measured caps

`POST /api/resample` (`src/bin/web.ts:69-88`) validates origin/content-type/body but — unlike `/api/backtest` (`web.ts:44`) and `/api/trades/resample` (`web.ts:93`) — never takes the `SingleFlight` lock. Behind it, `simulatePaths` (`src/resample/path.ts:130`) is fully synchronous, and the accepted envelope is `paths ≤ 20,000` (`src/resample/analysis.ts:40`) × `horizonTrades ≤ 1,000,000` (`analysis.ts:63`). Mode `both` plus audit, sizing ladder, and OOS each re-simulate; `summarizePaths` (`src/resample/stats.ts`) retains every curve and sorts per step for the fan bands. A single legal request can block the event loop for minutes or exhaust memory, and concurrent requests multiply it. Loopback-only binding limits the attacker surface to local processes, but a browser tab with two heavy runs can still hang the server for every panel.

**Upgrade direction.** Take the same SingleFlight lock; bound the paths×horizon product; chunk or offload path simulation (worker thread) so the server stays responsive; stream or cap curve retention in `summarizePaths`.

### C3 — Liquidation ends the run at mark equity, and the two paths disclose it inconsistently · P1 · code-level

On a maintenance breach the loop records `liquidatedAtBar/Price` and stops (`src/engine/loop.ts:401-402`) without modelling a liquidation fill; final equity for a non-flat book is `last?.equityAtMark ?? book.cash` (`loop.ts:452`) — i.e. the settlement mark, not breach proceeds. The legacy path says so explicitly: "Ending equity uses the settlement mark, not liquidation proceeds" (`src/backtest-api.ts:554`). The model path's warning omits that sentence: "Modeled maintenance breach; no liquidation fill price or liquidation fee is applied" (`backtest-api.ts:387`). Since the UI always uses the model path, users see liquidated runs whose ending equity silently includes unrealized mark PnL after the breach bar.

**Upgrade direction.** Either model a liquidation close (proceeds, fee) or make the model-path warning match the legacy disclosure verbatim; label the metric "equity at mark" for liquidated runs in the UI.

### C4 — Resample paths keep trading after bankruptcy · P2 · code-level

`walkPath` sets `bankrupt = true` when equity ≤ 0 (`src/resample/path.ts:79`) but continues applying subsequent trades; under compound sizing a negative equity base flips the sign of sized PnL. Bankruptcy rate is reported, yet the tail statistics (CVaR, p05) include post-bankruptcy resurrection trades. **Direction:** stop the walk at bankruptcy (or clamp equity at zero) and document the choice; add a canary pinning the behavior.

### C5 — Documented approximations worth revisiting · P2 · code-level

- Intrabar path folds candle extremes into the bar whose settlement closes them (`src/history/bars.ts`, `withIntraBarPath`), so extremes can include post-settlement prices; disclosed, but it biases maintenance checks.
- Markout uses `candlePriceAt` approximation at the 1 h horizon (`src/backtest-api.ts`).
- Relative windows default `to=now`, so identical lookback requests never share a cache entry (see C1).

## 3. Web design — delegated design-agent review

Attribution: the plugin design agent (`fullstack-dev-group:涂悦目`) could not spawn on this Windows host (agent meta-filename contains `:` → `EINVAL`); the review was performed by a general-purpose agent briefed as a senior UI designer, with live browser access plus code review. Findings it could only assess at code level are marked. The lead reviewer independently re-verified P0-2 (computed `fill: rgb(0,0,0)` on fan-chart labels; the only SVG-text rule is `#chart text{fill:#a7b6cf…}` in `public/app.css`, which does not cover `Resample.tsx` charts), the sticky overlap, the failure state, and the mobile layout.

**Already strong:** distinctive brand/hero, coherent cyan-violet dark palette, honest copy and badge discipline ("MODELLED FILL", small-sample warnings, "not a forecast"), muted text at 7.6:1 contrast, skip-link and focus-visible rings, custom scrollbars, `aria-busy` + form disable while running, clean mobile collapse with no page overflow.

### P0
1. **Failure state is misleading and unactionable** (observed live). After a failed run the Results panel still says "A hypothesis needs a test. Choose a market and set your position." with only a small RUN FAILED pill (`src/web/Results.tsx:50`), while the config alert prints the raw OS error (`src/web/App.tsx` catch path). Direction: a dedicated failure state in Results, human-mapped error copy with raw text in a collapsible detail, and a pointer to the working Import/Wallet resamplers.
2. **Resample chart axis labels are black on the dark panel** (observed + verified). Fan chart "1,035 / 0 / 12 trades" compute to `fill: rgb(0,0,0)` ≈ 1.2:1 contrast; the `#chart text` rule only styles the equity chart (`src/web/Resample.tsx:35,40-41,207`). Direction: one `svg text` fill/font rule for all charts.

### P1
3. **Sticky empty-state box paints over metrics** (measured: panel bottom y=448 vs first metric row top y=423 at 1440×900; `public/app.css:34` `.chart-sticky{position:sticky;top:16px;z-index:3}`). The `--chart-clearance` scroll-margin (`Results.tsx:31-47`) fixes anchor jumps, not wheel scrolling. Direction: disable sticky until a real curve exists.
4. **Charts under-labeled and unitless** (observed + code-level). Fan chart: one mid y-tick, no quote unit on canvas (`Resample.tsx:30,35`); histogram: no axes (`Resample.tsx:46-58`); metric cards show bare numbers with units only in hover `title`. Direction: 3–5 y-ticks, min/max, visible quote unit, starting-equity baseline.
5. **Shuffle's degenerate distribution reads as a bug** (observed). Static-size shuffle is order-invariant in finals: p05/p95 both 1,070.4, single-block histogram "1,070 … 1,070", no explanation. Correct math, wrong impression. Direction: inline note that shuffle moves path-dependent risk (drawdown/streaks), not finals.
6. **Validation feedback detached from fields** (observed). Empty custom dates / from>to errors appear only in the bottom alert while the offending inputs are off-screen; date inputs lack `required`/`aria-invalid` (`Configuration.tsx:61,93-94`). Wallet "abc" → red border + silently disabled button, no format hint (`Wallet.tsx:70,73`). Direction: inline field errors, focus/scroll to first invalid field, "0x + 40 hex chars" hint.
7. **Tiny type and small touch targets** (measured by agent). Pills 8 px, metric captions/chart-footer 9 px; segmented controls 34 px, checkboxes 16 px (<44 px). Direction: raise minimum label sizes and tap areas.

### P2
8. Equity chart is static — start/end labels only, no hover/crosshair/trade markers (code-level, `src/web/Chart.tsx:42-50`) — weak for the hero output of a backtest lab.
9. Resample tabs lack the a11y the Details tabs have — no `aria-controls`/`labelledby`, roving tabindex, arrow keys (code-level, `Resample.tsx:151` vs `Details.tsx:47-52`).
10. Stale results: editing the wallet address after a run leaves the prior result visible with no staleness marker (observed, `Wallet.tsx`).
11. Failure activity text is cyan like success (`.activity`); only the pill differs (observed).
12. Housekeeping (observed/measured): three independent `GET /api/markets` on load (Configuration, Wallet, ImportTrades — no shared cache); `/favicon.ico` 404; import "Resample" button full-bleed vs wallet's inline; metric definitions only in hover tooltips.

## 4. What works end-to-end on this machine (measured/observed)

- Legacy-path backtest API (HTTP 200) — the engine itself is sound; 31/31 engine tests pass.
- Wallet panel: invalid address gated client-side; valid zero address → live indexer query → honest "No closed trades in this window." with gross-PnL disclosure.
- Import panel: 12-trade CSV → 1000-path resample with fan chart, histogram, stats; Shuffle/Bootstrap toggle live (bootstrap correctly produces varying finals: p05/p95 991.79/1,144.7); graceful degradation when market history can't load (edge null excluded, warning shown).
- Mobile ≤650 px: top-bar collapse, stacked panels, charts fit, no page-level horizontal overflow.
